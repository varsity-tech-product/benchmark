# v4.0 — 12-Column Extended Kline Data Pipeline & Custom Backtest System

## Overview

This document describes the 12-column extended kline data pipeline and custom-data backtest mode added in the `rick-12col-backtest` branch. The system enables LEAN backtesting strategies to access per-side taker/maker volume breakdown — 6 additional fields beyond standard OHLCV — by aggregating directly from Binance's raw aggTrades archive.

## Architecture

```
data.binance.vision (raw aggTrades)
  │
  │  fetch_and_aggregate.py
  │  downloads daily ZIP files, streams CSV lines
  │  through StreamingKlineAggregator (constant memory)
  │
  ▼
12-column zip-sliced files
  {output}/{resolution}/{symbol}/{slice_key}_trade.zip
  │
  │  mounted at /data/custom/ in Docker container
  │
  ▼
LEAN engine (custom data mode)
  │  Strategy uses BaseData subclass with Reader()
  │  that parses all 12 columns
  │  inject_strategy.py injects: SetAccountCurrency,
  │  FeeModel, TradingDaysPerYear
  │
  ▼
Backtest results (JSON)
```

## 12-Column Format

Each kline bar has 12 fields (no header, comma-separated):

| Index | Field | Type | Description |
|-------|-------|------|-------------|
| 0 | open_time | int | Millisecond Unix timestamp |
| 1 | open | float | Open price |
| 2 | high | float | High price |
| 3 | low | float | Low price |
| 4 | close | float | Close price |
| 5 | volume | float | Total traded volume |
| 6 | taker_buy_volume | float | Buyer-initiated volume |
| 7 | taker_sell_volume | float | Seller-initiated volume |
| 8 | taker_buy_quote_volume | float | Buyer-initiated quote volume |
| 9 | taker_sell_quote_volume | float | Seller-initiated quote volume |
| 10 | taker_buy_trades | int | Count of buyer-initiated trades |
| 11 | taker_sell_trades | int | Count of seller-initiated trades |

**Taker direction logic**: Each aggTrade has an `is_buyer_maker` (`m`) flag.
- `m=false` → buyer is taker (active buy) → taker_buy_*
- `m=true` → seller is taker (active sell) → taker_sell_*

These are exact per-side splits aggregated from individual trades, not derived or approximated.

## Data Pipeline

### Script: `bench/scripts/fetch_and_aggregate.py`

Self-contained script with no external dependencies beyond `aiohttp` and `tqdm`. Downloads raw aggTrades from Binance's public data archive and aggregates into 12-column klines.

**Usage:**

```bash
# Single symbol, single interval
python bench/scripts/fetch_and_aggregate.py \
    --symbol BTCUSDT \
    --start 2022-01-01 \
    --end 2025-12-31 \
    --interval 1h \
    --output-dir bench/data/12col

# Multiple intervals
python bench/scripts/fetch_and_aggregate.py \
    --symbol BTCUSDT \
    --start 2022-01-01 \
    --end 2025-12-31 \
    --interval 1m,1h,1d \
    --output-dir bench/data/12col

# COIN-margined contract
python bench/scripts/fetch_and_aggregate.py \
    --symbol BTCUSD_PERP \
    --start 2024-01-01 \
    --end 2024-12-31 \
    --interval 1h \
    --output-dir bench/data/12col \
    --contract-type coin

# Skip gap filling
python bench/scripts/fetch_and_aggregate.py \
    --symbol BTCUSDT \
    --start 2024-01-01 \
    --end 2024-12-31 \
    --interval 1h \
    --output-dir bench/data/12col \
    --no-gap-fill
```

**How it works:**

1. **Download** — Fetches daily ZIP files from `data.binance.vision/data/futures/um/daily/aggTrades/{SYMBOL}/`. Async with configurable concurrency, retry with exponential backoff, 404 tolerance.

2. **Parse** — Each ZIP contains a CSV: `agg_trade_id, price, quantity, first_trade_id, last_trade_id, timestamp_ms, is_buyer_maker`. Only `p, q, T, m` are extracted into `AggTradeLite` (lightweight NamedTuple).

3. **Aggregate** — `StreamingKlineAggregator` processes trades one at a time. Each trade is assigned to a time window via `floor(timestamp_ms / interval_ms) * interval_ms`. A `_KlineState` object per window accumulates OHLC and 6 directional fields. Constant memory — no trade list stored.

4. **Gap fill** — After aggregation, missing time windows are forward-filled: OHLC = previous close, all volumes/counts = 0. Matches the upstream database pipeline behavior. Use `--no-gap-fill` to skip.

5. **Write** — Klines are grouped into zip slices:
   - Minute/hour intervals: daily slices (`YYYYMMDD`)
   - Daily interval: monthly slices (`YYYYMM`)
   - Path: `{output}/{resolution}/{symbol}/{slice_key}_trade.zip`
   - Each zip contains one CSV entry: `{slice_key}_{symbol}_{resolution}.csv`

**Supported intervals:** `1s, 1m, 3m, 5m, 15m, 30m, 1h, 2h, 4h, 6h, 8h, 12h, 1d`

**Memory:** Peak memory = one day of `_KlineState` objects per interval. For `1h` over 4 years: ~35K states — negligible.

## Backtest System — Custom Data Mode

### Two Modes

| | Standard (default) | Custom |
|---|---|---|
| Data format | 6-column Lean-native OHLCV | 12-column extended kline |
| Brokerage model | Default Lean backtesting brokerage | Injected `_BacktestBrokerageModel` (Margin, 20x leverage, zero slippage) |
| Fee model | Brokerage model default | Injected `_BacktestFeeModel` (maker=0.02%, taker=0.05%, configurable) |
| Code injection | None | 5 injections (see below) |
| Strategy data access | `AddCryptoFuture()` → Lean `TradeBar` | Custom `BaseData` subclass with `Reader()` |
| Activate with | (default behavior) | `--data-mode custom --symbol BTCUSDT` |

### Strategy Code Injection

Script: `bench/scripts/inject_strategy.py`

When `--data-mode custom` is passed to `run_backtest.sh`, the script applies up to 5 source-code transformations before compilation:

1. **`GetSource()` injection** — If a `BaseData` subclass lacks `GetSource()`, one is injected pointing to the custom data path. Classes that already have `GetSource()` are left untouched (no path rewriting).

2. **`SetAccountCurrency()` + `SetBrokerageModel()`** — Injected as the first statements in `Initialize()`:
   - `SetAccountCurrency("USDT")` — eliminates the need for USDTUSD currency conversion feeds.
   - `SetBrokerageModel(new _BacktestBrokerageModel())` — sets the brokerage model (see below).

3. **`_BacktestBrokerageModel`** — An inline brokerage model class injected before the strategy class. Provides:
   - `AccountType.Margin`
   - `GetLeverage()` → 20x for CryptoFuture (this is the **default**; strategies can override with `security.SetLeverage()`)
   - `GetFeeModel()` → `_BacktestFeeModel` with maker=0.02%, taker=0.05%
   - `GetSlippageModel()` → `ConstantSlippageModel(0)` (zero slippage)
   - `DefaultMarkets`: CryptoFuture → Binance

4. **`_BacktestFeeModel`** — An inline fee model class injected alongside the brokerage model. Calculates fees as `positionValue × rate` where rate is maker (limit resting) or taker (market/stop). Default rates can be overridden via algorithm parameters `maker-fee-rate` and `taker-fee-rate` — if custom rates are provided in the Lean config, a per-security override is applied at the end of `Initialize()`.

5. **`TradingDaysPerYear`** — Injects `Settings.TradingDaysPerYear ??= 365` for correct crypto annualization (Lean defaults to 252 for equities).

All injections are **idempotent** — they check for existing code before injecting.

### run_backtest.sh Changes

New flags:
- `--data-mode custom|standard` (default: `standard`)
- `--symbol BTCUSDT` (required for custom mode)

When `--data-mode custom`:
1. Step 1b runs `inject_strategy.py` on the algorithm source
2. Step 2b auto-injects these Lean config parameters:
   - `maker-fee-rate`: `0.0002`
   - `taker-fee-rate`: `0.0005`
   - `custom-data-root`: `/data/custom`

#### Post-v4.0 hardening (see issue #33)

- Config patches are applied to the **project-source** `config.json`
  (`${LEAN_ROOT}/Launcher/config.json`), not the `bin/Debug/config.json`
  copy. The runner launches LEAN with `dotnet run --no-build -c Debug`
  from `${LEAN_ROOT}/Launcher`, so the engine's relative `config.json`
  lookup resolves to the source file. The reference generator's path
  is different — it invokes the Launcher DLL directly from bin/Debug,
  so it writes its own config there.
- The runner now writes both `algorithm-type-name` **and**
  `algorithm-location` (pointing at the freshly copied DLL). Missing
  `algorithm-location` was the cause of LEAN's
  `JobQueue.NextJob … ReadAllBytes("")` crash.
- Config patching is delegated to `bench/docker/lean_config.py` —
  one helper imported by both this runner and
  `bench/reference_generator/generate_lean_reference.py` so the two
  can't drift apart.
- Container/image layout is parametrised via `LEAN_ROOT` (default
  `/lean`) and `LEAN_HELPERS_DIR` (default `${LEAN_ROOT}/helpers`).
  Forks with a capitalised `/Lean` layout only need to set one env
  var.
- Compiled-DLL discovery uses `find` instead of a hardcoded path so
  TFM bumps (net10.0 → net11.0 → …) don't break the runner.

## Writing a Custom Data Strategy

A strategy that uses the 12-column data needs:

1. A `BaseData` subclass with `GetSource()` and `Reader()`:

```csharp
public class ExtendedKline : BaseData
{
    public decimal TakerBuyVolume;
    public decimal TakerSellVolume;
    public decimal TakerBuyQuoteVolume;
    public decimal TakerSellQuoteVolume;
    public int TakerBuyTrades;
    public int TakerSellTrades;

    public decimal BuyPressure => Volume > 0
        ? TakerBuyVolume / Volume : 0.5m;

    public override SubscriptionDataSource GetSource(
        SubscriptionDataConfig config, DateTime date, bool isLiveMode)
    {
        // Reads zip#entry from pipeline output
        var dateStr = date.ToString("yyyyMMdd");
        var sym = config.Symbol.Value.ToLowerInvariant();
        var zip = $"/data/custom/hour/{sym}/{dateStr}_trade.zip";
        var entry = $"{dateStr}_{sym}_hour.csv";
        return new SubscriptionDataSource(
            zip + "#" + entry,
            SubscriptionTransportMedium.LocalFile,
            FileFormat.Csv);
    }

    public override BaseData Reader(
        SubscriptionDataConfig config, string line,
        DateTime date, bool isLiveMode)
    {
        var c = line.Split(',');
        if (c.Length < 12) return null;
        var ts = long.Parse(c[0]);
        return new ExtendedKline {
            Symbol = config.Symbol,
            Time = DateTimeOffset.FromUnixTimeMilliseconds(ts).UtcDateTime,
            EndTime = DateTimeOffset.FromUnixTimeMilliseconds(ts)
                .UtcDateTime.AddHours(1),
            Value = decimal.Parse(c[4]),
            Open = decimal.Parse(c[1]),
            High = decimal.Parse(c[2]),
            Low = decimal.Parse(c[3]),
            Close = decimal.Parse(c[4]),
            Volume = decimal.Parse(c[5]),
            TakerBuyVolume = decimal.Parse(c[6]),
            TakerSellVolume = decimal.Parse(c[7]),
            TakerBuyQuoteVolume = decimal.Parse(c[8]),
            TakerSellQuoteVolume = decimal.Parse(c[9]),
            TakerBuyTrades = int.Parse(c[10]),
            TakerSellTrades = int.Parse(c[11]),
        };
    }
}
```

2. Subscribe in `Initialize()`:

```csharp
_kline = AddData<ExtendedKline>("BTCUSDT", Resolution.Hour).Symbol;
```

3. Use in `OnData()`:

```csharp
var bar = slice[_kline] as ExtendedKline;
if (bar.BuyPressure > 0.55m) { /* buy signal */ }
```
